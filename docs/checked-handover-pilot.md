# Checked handover before reassignment

The protected operator can run `pnpm fleet handover CONFIG PROOF_FILE` against the
existing controller. It reads exact predecessor history, current claim generation,
central workflow and every native task. It reconstructs each named required file
through the shared store's verified reads. A pointer to local evidence cannot pass.
Every later ticket role already has evidence and native-task read access through
the existing bridge. No transcript, remote shell or fetch service is added.

The saved proof file names ticket, runId, generation, commit, remoteCommit,
remoteCheckedAt, evidenceDigest and requiredFiles. A protected operator must first
read the exact branch reference from GitHub. Use its 40-character SHA for both
commit values and a millisecond timestamp no older than 60 seconds. Do not treat
an agent's claim about a push as independent remote proof. The result is a
preflight. It never frees a claim and does not survive another workflow change.

## Why active reassignment is skipped

Current completion uploads evidence asynchronously and the store can evict an
older required bundle under its size cap. Release after a momentary successful
read would permit a later stage to lose its evidence. A protected exact remote
check is not yet part of the normal completion protocol. Automatically releasing
claims now would cross an unproven ownership boundary. No elapsed heartbeat,
missing report or timer can supply stopped-process proof.

The tested shadow selector is disabled by default. It recommends one eligible idle
Linux computer after 60 seconds of previous-computer preference. It makes no grant
and is not a scheduler. Keep it out of admission until the following migration.

## Complete migration and rollback

1. Add a versioned completion request. Bind run generation, exact pushed branch
   SHA, workflow revision and the required evidence manifest to one request ID.
2. Make the existing trusted publication path confirm the remote SHA. Upload and
   read back every required file before successful completion. Keep summaries and
   failure records. Reject absent, oversized or local-only required artifacts.
3. Pin accepted required bundles while the ticket is active. Refuse new upload
   rather than evict a required bundle when storage is full. Make backup and
   retention understand these pins. Add a tested unpin rule for final completion.
4. Settle native tasks and verdict publication before committing handover. Preserve
   existing generation checks and confirmed process-group exit. A failed or
   uncertain predecessor keeps ownership.
5. In one central transaction compare all revisions, record handover and choose
   one next computer. Offers remain suggestions. The existing grant decides.
6. Enable one Linux project behind configuration after an approved isolated
   runtime test. Preserve previous-computer preference for 60 seconds. Exclude
   the Mac, native-only jobs and tickets with unsettled work.
7. Measure blocked-stage minutes, rejected handovers and manual evidence retrieval
   for seven days. Compare with a pre-pilot week. Expand only after review.

Rollback disables new transfers first. Existing in-flight generations stay held.
Keep handover records and evidence pins readable until all recipients finish.
Never restore an old claim over a running successor. No configuration, live claim,
service, pin or target is changed by this pull request.
