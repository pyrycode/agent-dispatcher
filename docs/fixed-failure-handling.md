# Fixed failure handling

Known causal dependencies wait without calling a model. A recorded coordination
relationship can still receive an assessment. Authentication refusal, missing
platform or toolchain readiness and a definite publication refusal keep their
failure evidence. They do not clear errors or assign product rework.

The existing settlement records reopen a wait after relevant evidence, dependency
or capability changes. Unknown failures remain visible and use the existing
read-only assessment. New assessments use light capacity. During rollout the
service also accepts an old worker's heavy assessment, without releasing its run.
One assessment at a time, ownership checks and provider pacing remain in force.

Infrastructure retries have a separate durable count for each ticket and stage.
A restart, another computer, a day passing and an assessment's retry-reset text
cannot reset it. The default allowance is two. Configure
`recovery.infrastructureRetries` from 0 to 10 in the protected claims configuration.
Raise it only after reviewing the retained cause. Code rework keeps its existing
review counter. A lost decision reply consumes no second retry.

No provider session reservation is assumed. Existing pacing stays unchanged until
Juhana decides how much capacity to reserve for personal work.

Roll out the controller before new light assessment offers. Check a known blocked
ticket produces a recorded wait without a model call. Check an unknown error still
receives assessment, the retry allowance survives a restart and a heavy test can
coexist with a read-only assessment. Rollback retains the new table and its counts.
An old controller does not enforce those counts, so keep recovery paused while
rolling back. No live configuration is changed by this pull request.
